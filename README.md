# 하루 — 자영업자 협업 운영 유틸리티

작은 가게의 하루짜리 협업을 **등록 → 운영 확인 → 준비 목록 → 문서 → 정산 → 기록**으로 관리하는 한국어 모바일 우선 웹앱입니다. 실제 계정 인증과 서버 데이터베이스를 사용하며 외부 서비스 키 없이 실행됩니다.

## 실행

Node.js 24 이상이 필요합니다. 기존 체크아웃을 사용합니다.

```sh
cd /workspace/f-b_tools
npm ci --cache /tmp/haru-npm-cache
npm run dev
```

기본 포트는 `3000`입니다. 브라우저에서 회원가입한 뒤 가게를 등록하세요. 데모 계정이나 가짜 협업은 자동 생성하지 않습니다. `GET /api/health`가 `{"ok":true}`를 반환하면 서버와 데이터베이스가 응답하는 상태입니다.

```sh
npm test
npm run build
```

## 저장과 동시 수정

기본 데이터 파일은 `data/haru.sqlite`입니다. SQLite WAL 모드와 외래 키를 사용합니다. 입력은 약 0.5초 후 저장하며, 문서는 초안 자동 저장과 별도 버전 저장을 구분합니다. 화면 상단의 저장 상태와 실패 메시지를 확인할 수 있습니다. 네트워크 오류 시 협업 변경사항은 화면에서 유지되며 재시도할 수 있습니다. 저장 대기 중 브라우저 종료 시 경고합니다. 오프라인 저장은 지원하지 않습니다.

협업 변경에는 리비전 번호를 사용해 다른 창의 수정을 조용히 덮어쓰지 않습니다. 충돌 시 입력 내용을 따로 보관하고 새로고침 후 확인해야 합니다. 신규 협업 임시 입력과 문서 초안은 같은 계정의 마지막 저장값을 사용합니다. 완료된 협업의 체크리스트·메모·정산은 잠그며 정산을 다시 열면 수정할 수 있습니다.

## 정산 기준

- 협업자 지급액 = 기본 지급액 + 추가 지급액
- 총비용 = 식재료비 + 기타 직접비 + 협업자 지급액
- 기여이익 = 총매출 − 총비용
- 기여이익률 = 기여이익 ÷ 총매출 × 100; 매출 0원일 때 `—`

모든 금액은 정수 원 단위이며 0원과 적자를 허용합니다. 세전 지급액으로 통일해 입력합니다. 입력하지 않은 임대료·세금·수수료는 자동 추정하지 않습니다.

## 운영 배포

```sh
npm run build
# RESEND_API_KEY는 호스팅의 비밀 설정에 입력합니다.
MAIL_FROM="Haru <hello@your-verified-domain.example>" \
APP_ORIGIN=https://your-domain.example \
DATABASE_PATH=/absolute/persistent/path/haru.sqlite \
PORT=3000 npm start
```

- HTTPS 리버스 프록시 뒤에서 단일 Node 프로세스로 실행하세요. `APP_ORIGIN`은 실제 공개 주소이며 비밀값이 아닙니다. 프로덕션은 이 설정(또는 Render의 `RENDER_EXTERNAL_URL`)과 메일 발송 설정 없이는 시작하지 않으며 세션 쿠키에 `Secure`를 사용합니다.
- 프록시는 원래 `Host`를 보존해야 합니다. 요청의 Origin을 설정된 공개 주소와 검사합니다. 기본적으로 forwarded 헤더를 신뢰하지 않으며 Render에서는 실제 프록시 경로에 맞춰 `TRUST_PROXY_HOPS=1`을 설정합니다.
- 데이터베이스 경로는 영구 볼륨에 두고 접근 권한과 백업·복원을 운영 환경에 맞춰 설정하세요. 일관된 백업에는 SQLite backup API를 사용하거나 서버를 중지한 상태로 백업하세요. WAL 사용 중 주 DB 파일만 복사하면 안 됩니다.
- 세션 토큰은 DB에 SHA-256 해시로, 비밀번호는 사용자별 salt를 둔 scrypt 해시로 저장합니다. 쿠키는 HttpOnly·SameSite=Lax이고 세션은 로그아웃·만료 시 무효화됩니다. JSON 본문 크기 제한, 입력값 검증과 인증 시도 제한을 적용합니다.
- 프로덕션은 Resend를 통한 이메일 확인 후 이용할 수 있습니다. 확인 링크는 24시간, 비밀번호 재설정 링크는 30분 유효하며 한 번만 사용할 수 있습니다. 토큰은 해시로 저장하며 비밀번호 변경 시 기존 세션을 모두 무효화합니다. 개발 모드에서는 외부 메일 없이 기존 흐름을 테스트할 수 있습니다. 인증 요청 제한은 SQLite에 보관합니다. MFA, 계정 삭제, 관리자 도구는 아직 제공하지 않습니다. 공개 전 개인정보 처리·외부 백업·문의 대응 방침은 운영자가 정해야 합니다.
- SQLite 단일 인스턴스 MVP입니다. 여러 서버 간 수평 확장, 가게 직원 초대·공동 편집 권한은 제공하지 않습니다.
- 외부 결제, 송금, 전자서명, 세금 신고, POS 연동은 포함하지 않습니다.

Render의 영구 디스크를 사용하는 Node.js 배포 설정이 포함되어 있습니다. GitHub `main`과 Render 서비스가 연결되어 있으며 사용자가 공개 앱 동작을 확인했습니다. 운영 주소는 https://haru-ocke.onrender.com/ 이고 메일 발신 도메인은 `mail.huphuphan.org`입니다. 실행 환경의 외부 접속 제한 때문에 여기서 운영 상태를 직접 조회한 것은 아닙니다. 단계별 절차는 [공개 서비스 배포 안내](docs/DEPLOYMENT.md)를 참고하세요. 프로덕션은 시작 시 및 12시간마다 검증한 DB 백업을 최근 14개까지 보관합니다. 같은 디스크의 백업은 외부 백업을 대신하지 않습니다.

## 운영·문서 안내의 한계

앱은 법적 적법성, 근로자성 또는 납세 처리를 자동 판정하지 않습니다. 사업자등록 여부만으로 근로관계를 구분하지 않으며, 실제 지휘·감독 등 사실관계 확인을 안내합니다. 음식 판매와 외부 조리 음식 반입은 영업신고 범위·제조 장소 등을 관할 보건소에 확인하도록 안내합니다.

생성 문서는 빈 항목이 남은 검토 초안입니다. 특히 **일일 근로조건 확인서는 완성된 법정 근로계약서가 아닙니다.** 필요한 법정 사항을 확인하고 고용노동부 공식 표준근로계약서 등으로 최종 작성해야 합니다. 일괄적인 세율, 최저임금, 가산수당 또는 성과급 공식을 추정하지 않습니다.

## 검증

`npm test`는 실제 HTTP 서버와 임시 SQLite 파일로 회원가입·로그인, 중복 이메일, 해시 저장, 세션 무효화·만료, 사용자 및 가게 간 데이터 분리, 잘못된 날짜·금액 거절, 신규 입력 임시 저장, 체크리스트·메모, 리비전 충돌, 문서 생성·초안 저장, 정산·완료 잠금, 서버 재생성 후 영구 저장, 교차 사이트 요청 차단을 확인합니다.

`npm run build`는 TypeScript 타입 검사와 Vite 프로덕션 번들을 생성합니다. 브라우저 인쇄의 PDF 저장 옵션은 브라우저마다 명칭이 다를 수 있습니다.

### 브라우저 검증

Chromium이 설치된 환경에서 실행 중인 개발 서버를 대상으로 다음을 실행할 수 있습니다. 실제 테스트 계정과 가게를 생성하므로 테스트용 DB로 서버를 실행하세요.

```sh
# 첫 터미널
DATABASE_PATH=/tmp/haru-browser-test.sqlite npm run dev
# 두 번째 터미널
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

이 검증은 회원가입, 가게 등록, 3단계 협업 등록, 체크리스트·메모 자동 저장, 문서 초안·별도 버전·PDF 출력, 347,000원 정산, 완료·기록, 모바일 넘침 검사 및 로그아웃 후 재로그인 데이터 복원을 포함합니다. 결과 이미지와 PDF는 기본 `/tmp/haru-artifacts`에 저장됩니다. `HARU_BASE_URL`, `HARU_ARTIFACTS`로 대상과 결과 위치를 바꿀 수 있습니다.

이메일 확인·비밀번호 재설정의 모바일 화면은 `npm run test:account-browser`로 검증합니다. 이 테스트는 임시 메모리 DB와 테스트 메일 처리 함수를 사용하며 실제 외부 수신자에게 메일을 보내지 않습니다.

안타르티카 예제의 수입·중복 방지·원문 보존·문서·모바일 흐름은 `npm run test:sample-browser`로 검증합니다. 임시 메모리 DB를 사용하며 운영 데이터에 접근하지 않습니다.
